# CJ LibreChat Fork Customizations

This file is the upgrade manifest for the `cj-custom` branch. Use it when rebasing onto a newer LibreChat release. It records intended behavior, affected files, and validation commands so custom behavior can be reimplemented if upstream changes conflict.

## Upgrade workflow

1. Fetch the desired upstream release into the fork's `main` branch.
2. Create a backup branch from the current `cj-custom` head.
3. Rebase `cj-custom` onto the updated `main` branch.
4. Resolve conflicts by preserving the behaviors below rather than blindly retaining old source.
5. Run the focused tests listed in each section and the bounded-heap TypeScript check.
6. Rebuild and deploy the LibreChat API image.
7. Verify the model picker, one CJ Router response, one direct streamed response, and mobile background recovery.

## 1. CJ Router source footer and bibliography cleanup

Purpose: present CJ Router evidence as a compact, collapsible source panel while removing a duplicate bibliography generated by the model.

Files:

- `client/src/components/Chat/Messages/Content/CJRouterFooter.tsx`
- `client/src/components/Chat/Messages/Content/MessageContent.tsx`
- `client/src/components/Chat/Messages/Content/Parts/Text.tsx`
- `client/src/components/Chat/Messages/Content/__tests__/CJRouterFooter.spec.tsx`
- `api/app/clients/BaseClient.js`

Required behavior:

- Recognize `CJ Router sources relied upon:` and the `CJ Router: Model:` statistics footer.
- Render the normal answer separately from a closed-by-default `Sources (N)` accordion.
- Strip duplicate model-generated source sections only when the authoritative CJ Router source block is present.
- Preserve model source lists on stats-only cloud responses.
- Handle CRLF input, inline and unheaded bibliographies, fenced code, and prose following a bibliography.
- Preserve footer/source metadata through provider response normalization.

Validation:

```bash

```

## 3. Cache-stable web-search runtime date

Purpose: preserve provider prefix-cache hits. An exact ISO timestamp near the beginning of every request changed the token sequence each turn and forced oMLX and hosted providers to prefill the complete conversation again.

Files:

- `packages/api/src/tools/toolkits/web.ts`
- `packages/api/src/tools/toolkits/web.spec.ts`

Required behavior:

- Supply `Current Date: YYYY-MM-DD` to web-search-enabled models.
- Keep the value stable throughout a UTC calendar day.
- Do not insert a per-turn clock time into the system prefix.
- Apply through the shared tool-context builder so legacy endpoints, agents, local models, and cloud providers receive the same cache-stable value.

Validation:

```bash
npx jest packages/api/src/tools/toolkits/web.spec.ts --runInBand
```

## 4. Mobile recovery for direct legacy SSE streams

Purpose: recover direct endpoint responses when iOS Safari suspends the page while locked. The LibreChat server may finish and persist the answer even though the browser misses the remaining stream.

File:

- `client/src/hooks/SSE/useSSE.ts`

Required behavior:

- Track whether an active legacy stream was backgrounded.
- On `visibilitychange`, `pageshow`, or `online`, query durable conversation messages.
- If the server has persisted an assistant child for the submitted user message, replace stale client state with authoritative messages and clear the submitting state.
- If generation is still running, poll briefly until the completed child is persisted.
- Stop reconciliation immediately when the normal final event arrives or the hook unmounts.
- Do not interfere with the separate resumable SSE path used by durable agent/background runs.

Manual validation:

1. Start a long direct oMLX response on an iPhone.
2. Lock the phone before the first token.
3. Wait for the server to complete the request and unlock the phone.
4. Confirm that the completed response appears without Retry or page reload.

## 5. Configurable web-search round limit

Purpose: prevent direct tool-using models from repeatedly broadening web research while still allowing several independent searches to run concurrently.

Files:

- `packages/data-provider/src/config.ts`
- `packages/data-provider/src/config.spec.ts`
- `packages/api/src/agents/webSearchRoundLimit.ts`
- `packages/api/src/agents/webSearchRoundLimit.spec.ts`
- `packages/api/src/agents/run.ts`
- `packages/api/src/tools/toolkits/web.ts`
- `packages/api/src/tools/toolkits/web.spec.ts`

Configuration:

```yaml
webSearch:
  maxSearchRoundsPerTurn: 2
```

Required behavior:

- Count a completed root tool batch containing one or more `web_search` calls as one search round.
- Treat parallel searches in the same batch as one round.
- After the configured number of rounds, deny only later `web_search` calls; leave other tools available.
- Tell the model after each completed search round how many search rounds remain and require a final answer after the last allowed round.
- Keep the static web-search tool context explicit that independent searches should be issued concurrently.
- Omission of `maxSearchRoundsPerTurn` preserves unlimited search rounds.

Validation:

```bash
npx jest packages/api/src/agents/webSearchRoundLimit.spec.ts packages/api/src/tools/toolkits/web.spec.ts packages/data-provider/src/config.spec.ts --runInBand
```

## CJ Router first-class web-search provider

LibreChat can use `searchProvider: cj_router` while retaining the normal `web_search` UI, citations, artifacts, concurrent tool-call batches, and `maxSearchRoundsPerTurn` enforcement. The model chooses each query. The provider performs Tavily advanced search (20 results), one advanced extraction batch for the top five unique URLs per query, table-aware chunking, and production-Cohere `rerank-v3.5` selection of the top 15 evidence chunks.

This provider deliberately does not run CJ Router's query planner or subquery planner, KB-card or Qdrant retrieval, source-quality classification, primary-source retries, software-capability repository discovery, extract-miss refetches, or experimental fetch policies. The existing CJ Router chat-completions paths retain their prior behavior.

Custom files:

- `packages/api/src/tools/cjRouterWebSearch.ts`
- `packages/api/src/index.ts`
- `packages/data-provider/src/config.ts`
- `packages/data-provider/src/types/web.ts`
- `api/app/clients/tools/util/handleTools.js`
- `LibreChat-Config/librechat.yaml`

The backend endpoint is `POST /v1/librechat/web-search` in `LiteLLM-Config-CJ-Router/cj_router/router.py`. It records component timings and selected evidence in both `librechat-cj-web-search.jsonl` and the central web benchmark ledger.
